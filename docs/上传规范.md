# DSH 技能上传规范

> 上传前必读。违反规范的技能 DSH 加载不了。

---

## 一、硬性规则

### 1. 技能标识符必须是 kebab-case

**只有 ASCII 小写字母、数字、连字符。**

```
✅ numeric-table-anchor-consistency
✅ office-docx
❌ 化学合规
❌ STD-ERP
❌ My_Skill
❌ image_gen_coze
```

不合规时 DSH 会提示「宿主不支持此技能名称格式，无法启用」。

**检查方法**：
```bash
grep -m1 '^name:' <技能目录>/SKILL.md | sed 's/^name:[[:space:]]*//' | tr -d '\r"'"'" \
  | grep -qE '^[a-z0-9]+(-[a-z0-9]+)*$' && echo 合规 || echo 不合规
```

### 2. 必须有 frontmatter

SKILL.md 开头必须是 YAML frontmatter，否则 DSH 完全不认：

```markdown
---
name: my-skill
description: |
  一句话说明这个技能做什么。
  触发词：关键词1、关键词2、关键词3
category: capability
version: "1.0.0"
agent_created: true
---

# 技能正文
```

> `description` 里的**触发词**很重要 —— DSH 靠它判断何时启用该技能。

### 3. 目录名建议与 name 一致

DSH 内置技能全部是"目录名 = name"（如 `office-docx/SKILL.md` 的 name 就是 `office-docx`）。
目录名可以用中文，但**上传到 GitHub 后建议统一改成英文 kebab-case**，避免跨平台问题。

### 4. 仓库是公开的，提交前必须脱敏

DSH 通过 `codeload.github.com` **匿名**拉取仓库压缩包，因此**本仓库必须是公开仓库**。

公开 = 任何人可读。以下内容**绝对不能提交**：

| 类型 | 示例 | 处理 |
|---|---|---|
| 密钥/令牌 | `ghp_`、`github_pat_`、`api_key`、`password:` | 删除，脚本会自动扫描拦截 |
| 本机路径 | `C:/Users/<用户名>/` | → `<USER_HOME>` |
| WorkBuddy 路径 | `~/.workbuddy/...` | → `<WORKBUDDY_HOME>` |
| 内网 IP | `192.168.x.x`、`10.x.x.x` | → `<INTERNAL_IP>` |
| 业务数据 | 客户名称、客户名单、报价 | 删除 |
| 内部信息 | 组织架构、人员姓名、内部制度 | 删除 |

`tools/sanitize.py` 自动处理前四类，最后两类需人工判断。

> **技能放方法论，不放公司业务。** 涉及客户名单/报价的做成插件，走私有 npm 仓。

## 二、上传流程

### 脚本方式（推荐）

```bash
bash tools/upload-skill.sh <技能名> "feat: 新增 XXX 技能"
```

脚本自动完成：定位源目录 → 校验 kebab-case → 脱敏 → 密钥扫描 → 提交推送。

### 手工方式

```bash
# 1. 克隆/更新仓库
git clone https://github.com/Zhong1856572/dsh-plugins.git
cd dsh-plugins

# 2. 放入技能
cp -r ~/.workbuddy/skills/<技能名> skills/<技能名>/

# 3. 脱敏
python3 tools/sanitize.py skills/<技能名>

# 4. 密钥扫描（命中即中止）
grep -rniE "ghp_|github_pat_|api[_-]?key|password[[:space:]]*[:=]|bearer [A-Za-z0-9]{20,}" skills/<技能名>

# 5. 同步清单（自动，别手改）
python3 tools/sync-manifest.py
python3 tools/sync-manifest.py --check

# 6. 更新 README 技能清单表

# 7. 提交推送
git add -A
git commit -m "feat(skill): 新增 <技能名>"
git push origin main
```

---

### 清单同步（不可跳过）

**每次上传技能后必须执行**：

```bash
python3 tools/sync-manifest.py            # 以 skills/ 目录为准反向生成清单
python3 tools/sync-manifest.py --check    # 校验，必须输出"✓ 清单一致"
```

脚本以 `skills/` 目录为唯一事实来源，会自动报出三类问题：
- 缺 `SKILL.md` 的目录
- 没有 frontmatter `name` 字段的
- `name` 不是 kebab-case 的

> **漏掉这一步 = 技能白上传。** 清单不更新，DSH Skills Manager 扫不到，
> 员工订阅后界面里看不到这个技能。

## 三、清单文件规范

### `dsh-plugins.json`

```json
{
  "$schema": "./dsh-plugins.schema.json",
  "version": 1,
  "repository": {
    "owner": "Zhong1856572",
    "name": "dsh-plugins",
    "ref": "main",
    "subdirectory": "skills"
  },
  "skills": [
    {
      "name": "my-skill",
      "path": "skills/my-skill",
      "description": "一句话说明",
      "version": "1.0.0",
      "category": "capability",
      "updatedAt": "2026-11-17T08:00:00+08:00"
    }
  ],
  "plugins": [],
  "updatedAt": "2026-11-17T08:00:00+08:00"
}
```

字段说明见 `dsh-plugins.schema.json`（JSON Schema，可直接被 IDE 校验）。

**每次上传技能，必须同时更新**：
1. `dsh-plugins.json` 的 `skills` 数组
2. `README.md` 的「技能清单」表格

## 四、员工怎么装

### 方式一：DSH 界面订阅（推荐）

1. 打开 DSH → **设置 → 技能** → **「发现」** 页签
2. **添加仓库** → 填 `Zhong1856572/dsh-plugins`
3. 确认扫描结果 → 逐个点击安装

### 方式二：命令行

```bash
git clone https://github.com/Zhong1856572/dsh-plugins.git
cp -r dsh-plugins/skills/<技能名> ~/.dsh/skills/
```

### 方式三：让 Agent 代劳

```
请从 GitHub 仓库 Zhong1856572/dsh-plugins 克隆仓库，
把其中的 skills/<技能名>/ 安装到我的 DSH 技能目录 ~/.dsh/skills/，
安装后告诉我如何让 DSH 重新加载。
```

## 五、常见报错

| 现象 | 原因 | 解决 |
|---|---|---|
| 「宿主不支持此技能名称格式，无法启用」 | name 非 kebab-case | 改成小写+连字符 |
| 订阅后扫不到技能 | 清单未登记 / 目录缺 SKILL.md | 更新 dsh-plugins.json |
| 订阅仓库失败 | 仓库被设为私有 | 改回公开（DSH 匿名拉取） |
| 安装后不生效 | 未重新加载 | 重启 DSH 或在设置里刷新技能 |
| 推送被拒 | 密钥扫描命中 | 按提示删除密钥后重试 |
