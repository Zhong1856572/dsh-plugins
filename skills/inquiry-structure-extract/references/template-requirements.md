# 固定模版的要求

脚本靠模版的表头认出「结构式」列，再按模版的合并单元格/行高/列宽把图放进去。
模版不对，产物就会错位。

## 一、硬性要求

1. **表头里必须有一列写着「结构式」**，可以是：
   - `结构式`
   - `结构式/产品信息`
   - `产品结构式`
   识别规则：表头单元格文字里包含「结构式」三个字即可。

2. **表头不能是第 1 行以外的多行复杂表头**。脚本按下面这个结构识别：
   - 第 1 行：标题行（大标题、合并单元格）——可空、可有
   - 第 2 行：表头行 —— 必须有「结构式」列
   - 第 3 行起：数据行

   如果你的模版表头在第 1 行，把标题行删掉即可。

3. **数据首行之前不要有别的内容行**。脚本从「表头行 + 1」开始写。

## 二、可选项（有就用，没有也能跑）

- **合并单元格**：`结构式` 列常常与右边几列合并成一大格，脚本会识别合并范围，
  把图按整格宽度等比缩放并居中，不会压到相邻列。
- **行高**：脚本按模版原有行高放图；行高太小会显得小，可在模版里调。
- **列宽**：同理。
- **空白行**：模版里预置的空行会被当成数据行占用；行数不够时脚本自动补行。

## 三、怎么检查一份模版合不合格

用工作台插件的检查接口（会打印列名、行数、可放图数量）：

```bash
node -e "import('./scripts/lib/template.js').then(async (m) => {
  const fs = await import('node:fs');
  const info = m.inspectTemplate(fs.readFileSync(process.argv[1]));
  console.log(info);
})" "<模版路径>"
```

关键字段：

| 字段 | 含义 |
|---|---|
| `targetColumn` | 「结构式」列的列号（字母） |
| `targetTitle` | 该列表头文字 |
| `headerRow` | 表头所在行号 |
| `dataStartRow` | 数据首行行号 |
| `availableRows` | 模版还能放多少张图 |
| `mergeEndColumn` | 该列合并到的最后一列 |

## 四、常见不合规情况

| 现象 | 原因 | 处理 |
|---|---|---|
| 找不到「结构式」列 | 表头写成了「结构式图片」以外的字（如「结构图」） | 改成含「结构式」的表头 |
| 图写到了错误的列 | 表头行不是第 2 行 | 调整表头行位置 |
| 图被压扁 | 模版行高过小 | 调高行高，或不合并单元格 |
| 产物行数比模版多 | 图数超过模版容量 | 正常现象，脚本自动扩展了行 |

## 五、模版文件本身

模版属于业务文件，**不要提交进代码仓库**（仓库 `.gitignore` 已排除 `*.xlsx`）。
把它放在本机，通过 `--template` 或 `TEMPLATE_XLSX` 指向它。
