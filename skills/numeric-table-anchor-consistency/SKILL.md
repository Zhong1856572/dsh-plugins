# 多表数值文档：跨表口径一致性 SOP

> 适用：一份方案正文（多张分档表）+ 一份试算表，或任何「同组参数在多处出现、必须处处一致」的交付物。
> 反例症状：改了一处忘另一处；两个页面互相打架；某档显示 0；小数点后两位对不上。

## 一、三条纪律（不可省）

1. **数值一律由模型常量 + 纯函数生成**，正文/表格里不出现手写数字。
2. **一条锚定式把关键档位钉死**，用 assert 保证它在生成前就成立。
3. **落盘后从产物文本反解每一格**，与模型逐格比对 —— 只校验最终数值会漏掉「两处错误相互抵消」和「同文件两页口径不一致」。

## 二、模型层写法

```python
BASE   = 5000.0                      # 基线
ANCHOR = 10000.0                     # 锚点档位
RATES  = [0.035, 0.045, 0.055, 0.065, 0.075]
SEGS   = [(5000,6000),(6000,7000),(7000,8000),(8000,9000),(9000,10000)]
FIX    = {"A": 45.0, "B": 20.0, "C": 15.0}
SHARE  = {"A": 0.35, "B": 0.50, "C": 0.15}
CEILING = 300.0
FIX_SUM = round(sum(FIX.values()), 2)

def pool(L):
    p = 0.0
    for (a, b), r in zip(SEGS, RATES):
        p += max(0.0, min(L, b) - max(a, BASE)) * D_COEF * r
    return p

def total(L):        return FIX_SUM + pool(L)
def ptotal(L, k):    return FIX[k] + pool(L) * SHARE[k]

# 锚定式：把「某档位 = 某目标值」写成恒等式，生成前就拦住
assert abs(sum(RATES) * 1000.0 * D_COEF - (CEILING - FIX_SUM)) < 1e-6, "费率组与锚定档不符"
assert abs(total(ANCHOR) - CEILING) < 1e-6, "锚定档未命中目标值"
```

**锚定式反解**：设「锚点档三人合计 = 目标值 M」，则 `Σrate × 段长 × D = M − 固定薪合计`。
段长相等时化简为 `Σrate = (M − FIX_SUM) / (段长 × D)`；再按「每档递增固定幅度」的整齐结构反解首档。

## 三、表格由循环生成，不手写行

```python
def row(L):
    emph = ' cell-emphasis' if L == ANCHOR else ''
    return ('<tr><td>%s</td><td class="cell-center%s">%s</td>...</tr>') % (L, emph, n2(total(L)), ...)

TB = "\n".join(row(L) for L in LADDER)
```

模板用 f-string 注入：`PAY_TABLE = f'''... {TB} ...'''`。

## 四、落盘后反解校验（最关键的一步）

从**产物文本**（HTML / xlsx / docx）读回，逐格与模型比对：

```python
m = re.search(r'表 2-1.*?<tbody>(.*?)</tbody>', html, re.S)
rows = re.findall(r'<tr>(.*?)</tr>', m.group(1), re.S)
for i, row in enumerate(rows):
    tds = [re.sub(r'<[^>]+>', '', t).strip() for t in re.findall(r'<td[^>]*>(.*?)</td>', row, re.S)]
    L = float(tds[0]); pool_v = float(tds[2]); tot_v = float(tds[3])
    assert abs(pool_v - pool(L)) < 5e-3
    assert abs(tot_v - total(L)) < 5e-3
    assert abs(z + zw + c - tot_v) < 5e-3      # 恒等式：分项之和 = 合计
```

**三组必查恒等式**：
1. 分项之和 = 合计
2. 固定薪 + 变动部分 = 总额
3. 占比 = 分子 / 分母（反向验算）

Excel 侧同理，且**逐格断言公式文本**（不只是数值）：

```python
eq(f"档位试算!D{r}", ws.cell(r, 4).value, "=参数与假设!$B$18")
```

## 五、坑位清单（全部实测踩过）

| 坑 | 症状 | 正解 |
|---|---|---|
| 跨表引用参数行号用连续偏移 | 整体错位一格，某档取到空行 → 显示 0 | 显式映射 `{6000:18, 7000:19, ...}`，禁止 `18+i` |
| 浮点断言容差过严 | `abs(0.275*1000*0.8-220.0) < 1e-9` 失败 | 容差用 `1e-6` |
| 锚定式系数写错 | 把「段长 1000 × D 0.8」写成单一系数 800，少乘一半 | 写全 `sum(RATES) * 1000.0 * D_COEF`，让断言拦住 |
| 旧值扫描误报 | 同一串既是旧值又是新值（如 `41.2%` 旧版合计占比 / 新版某人占比） | 先判断该串在新口径下是否合法，再决定是否入黑名单 |
| 历史说明段被误报 | 「本方案替代哪些旧版本」必须保留旧数字 | 扫描前用正则剔除该段，并单独 assert 它确实存在 |
| 段落占位符原样输出 | `{n2(CEILING)}` 没被替换 | 确认所在块是 f-string（`f'''`），漏了 `f` 会静默输出原串 |
| 覆盖前未查占用 | Word/WPS 打开着 → 写入失败 | 查 `~$` 锁文件；体积变化但内容未改时先 dump 比对再覆盖 |
| 覆盖前无回滚点 | 改坏无法退回 | 覆盖前 `cp` 一份 `_bak_<文件名>-<时间戳>` |
| 反解行号算多一行 | 表头占 2 行时数据从 R5 起，`max_row` 误写成 `5+N` | 统一 `4 + N`（2 行标题 + 1 行表头 + N 行数据），先 dump 真实 `max_row` 再写断言 |
| 合计行留空被当缺陷 | 「合计」行的说明列写空字符串，被空值扫描误报 | 合计行每格都要填语义化文字（如「不参与加权」），不留 `""` |
| `merge_cells` 传 4 个裸整数 | `ws.merge_cells(1,1,1,nc)` 报 `TypeError: argument of type 'int' is not iterable`（第 2 个位置参数被当 `range_string`） | 用 `ws.merge_cells(range_string="A1:%s1" % get_column_letter(nc))`，或 4 个关键字参数 `start_row=/start_column=/end_row=/end_column=` |
| 表头与数据元组长度错配 | 表头漏了某列（如「备选方案」）而数据里有 → 该列起整体错位，末列被静默丢弃 | 给每张表加「元组长度断言」（如 A/B=10、C=9、D=6、E=5），并在写循环里对齐表头项数 |
| 空值断言用 `range(1, nc+1)` 一刀切 | 把「待填白列」也纳入非空检查 → 大批假阳性（本轮 21 项误报） | 显式声明每表两类列：`FILLCOLS`（应空，留待填写）与 `NONEMPTY`（应有值，逐列列出），不连续段（如 A 表 9/10 空、11 有值）尤须显式列举 |
| 断言范围与真实结构脱节 | 断言写「C 行第 6 列非空」但第 6 列本就是待填列 → 误报 | 断言前先把「数据元组索引 → 表格列号」的映射列成表，逐条核对再写 `assert`，不凭记忆 |
| 否定语境被当违规 | 断言「不含『暂定值』」，但正确落地恰恰是**否定表述**「不设暂定值与重算环节」（docx 表2-0 α、表2-1 D 各 1 次）→ 假阳性 | 断言前先剔除否定串：`s2 = s.replace("不设暂定值与重算环节","")`，再 `assert "暂定值" not in s2`；并**正向**断言该否定串出现次数（=2）。同类词：试运行、有效询价数、封顶 |
| 多表共享一套结构假设 | 6 张表各有各的结构（本表 `r1 标题 / r2 副标题 / r3 空 / r4 表头 / r5 起数据`；D 表第 3/6 列名与 A 表不同；E 表仅 4 列且**无「序号」列**）→ 用「r1=表头、数据从 r2 起」统一假设，一次报 25 项假阳性 | 校验脚本写成 `SPEC = [(sheet名, 表头行, 数据起, 数据止, 列数, 决定列号或 None, 条数), ...]` **逐表显式声明**，循环里按声明取值断言，禁止任何「所有表都一样」的隐式假设 |
| **只校数据不校渲染** | 源数据 `Σ职能项权重 == 维度权重` 断言全过，但产物里维度块错位、权重挂到了别的维度名下 —— 数据层自洽、渲染层错乱 | 断言必须下沉到**渲染结果**：从产出文件反解「块内小计 == 该块维度权重」，并断言块顺序 == `DIM_ORDER`。数据自洽 ≠ 排版自洽 |
| **分组渲染 vs 源数据排列顺序** | 源列表按「职责域」排列（1.1…4.2、5.1、5.2），但分组键 `dim` 非连续（4.2 属增量归因、5.1/5.2 属组织能力）→ 用「首见即换块」的连续块逻辑，4.2/5.1/5.2 被静默并入上一块 | 按 `for dom in DOM_ORDER: block = [x for x in FUNC if x.dim == dom]` **显式分组**（不依赖相邻性），并对每块加小计断言。源列表的排序维度与分组维度不一致时，连续块逻辑必然出错 |
| **类名语义重载 → 校验脚本假阳性** | 同一类名 `fn` 同时用于 `.formula` 的公式脚注 div 和 `details.fn` 职能卡片 → `.count('class="fn"')` 得 19 而非 15，误报「卡片数不符」 | 计数时带上标签：`src.count('<details class="fn">')`；更好的做法是**给两者起不同类名**（脚注改 `.note`），从根上消除歧义。CSS 侧同时用 `.formula .fn` / `details.fn` 限定，避免串样式 |
| **死样式残留** | CSS 有 `hr.sep{...}` 但 HTML 里 `<hr>` 数量为 0（规则曾用过、改版后没人删）→ 长期误导维护者 | 落盘后做**双向类名对齐**：`CSS类名集合 \ HTML类名集合` 与反向，两侧都应为空（JS 动态类 `classList.add/toggle` 要单独抽取后并入「HTML 在用」集合，否则误报） |
| **断言正则被格式细节卡住** | `r"=== SHEET: ([^\s]+) \("` 匹配 `=== SHEET: 表1-1 职能总表  (19 行…)` 失败（表名含空格 + 括号前是两个空格）；编号抽取用半角 `\|` 而源文本是全角 `｜` → 抽取结果恒为 0 条 | 抽取正则一律写宽容版：`(.+?)\s+\(`，并**同时接受全角半角分隔符** `[｜|]`。抽取完先 `print(len(...))` 目视，再进入断言 |
| **「未检查」伪装成「通过」** | 抽取正则没命中 → 清单为空 → 断言循环体不执行 → 报告「0 项不符」，与「真通过」在输出上完全无法区分（本轮 `职能项编号 0 个` 静默漏检 15 项） | 每个检查段**先断言清单非空**：`ck(len(items) > 0, "抽取到 %d 条" % len(items))`。空清单必须报 FAIL 而不是 PASS —— 这是最危险的一类假绿 |
| 补丁脚本不幂等 | `insert_cells_after` 类脚本重复执行 → 同一位置反复插列，文件逐次损坏且无报错 | 补丁脚本开头加「已打过标记则直接退出」的幂等判断；执行前 `cp` 备份，**重跑一律先还原备份再跑**，不在上一次的输出上叠加 |
| 断言过严误报「用户手改」 | 断言「某串出现 2 次」，实际 1 次 —— 排查发现 docx 被用户在会话外手改（45321→59834 B），整段被删 | 交付脚本**不读回就无法察觉外部修改**。对比断言前先记录文件的 mtime 与 size，与上次留档比对；确属用户手改的，断言放宽并**以用户版为准**，同时在交付说明里显式告知 |
| **外部编辑器重存污染产物** | 用户在可视化编辑器里打开保存后：体积 124945→236012 B、标签被展开为 1266 行、注入 2590 个 `data-page-node-id`、多出 2 个 `<style>` 块（其中 `[data-sp-bindable="database"]` 会在页面元素上画出**蓝色虚线框**，属投影可见缺陷） | 复检与交付前先比对 size 与 mtime；确认重存后：① **先备份用户版**（`_bak_*-用户手改-<时间戳>`）再动手；② 清理全部注入物（属性 + 注入的 style 块）；③ 清理后用**结构计数断言**兜底——`table/details/tr/td` 逐一与清理前比对，证明只删注入物、零内容损伤 |
| **注入属性打穿精确标签断言** | 编辑器给每个标签都加了属性（`<details class="fn">` → `<details class="fn" data-page-node-id="…">`），使 `src.count('<details class="fn">')` 归零、`find('<details class="locked-zone">')` 返回 -1；更糟的是**连带**效应——后置的「宣讲区合规」检查因 `lock_idx = -1` 使 `body_zone = src[:-1]` 扩到全文，一次误报 4 项 | 断言一律用**属性容错正则**：`<details[^>]*\bclass="fn"`、`<style[^>]*>`、`<script[^>]*>`；凡「先定位锚点、再切片检查」的写法，必须处理**锚点未命中**分支（显式报 FAIL，不可静默退化为全文切片——那会把抽样检查变成必然失败，掩盖真实问题） |
| **机制参数被"合规"藏起来** | 为规避保密风险，把费率、折价系数、归因折扣系数、分配系数一律写成「（取值见方案正式文本）」→ 听众无法自行算出「能拿到多少」，宣讲目标落空；且与同文档内「分配系数最高」「费率逐段递增」的表述自相矛盾 | 划清**两类信息**的边界：**机制参数**（费率、系数、基线、档位、分档规则）是**制度设计**，属可讲内容，必须显式给出并保证能算通；**个体数据**（个人金额、个人考核得分）才是不进宣讲区的部分。落盘后加一条断言：`"正式文本" not in flat`，防止占位回潮 |
| **openpyxl 清值写法失效 → 证伪测试假通过** | 证伪测试里用 `ws.cell(row=3, column=1, value=None)` 注入「少一条记录」缺陷 → **实际未生效**（openpyxl `cell()` 源码是 `if value is not None` 才赋值，传 None 等于不写），缺陷件仍报全绿，差点误判为「校验器有效」 | 清值一律用 `ws["A3"] = None` 或 `ws.cell(row, column).value = None`。**证伪测试本身也要被验证**：注入后先读回确认缺陷确实落地（`assert wb["问题清单"]["A3"].value is None`），再跑校验器；注入（缺陷）与检出（FAIL）条数须能一一对应 |
| **合并单元格 + wrapText 的行高不自动** | 长文本写进合并区并设 `wrap_text=True`，Excel/WPS 打开时**不会自动调整行高**（合并区不参与自动行高计算）→ 内容被压成一行，下半截看不见 | 对合并长文本区**显式写行高**：`height = ceil(len(text) / (合并区总列宽 / 2.2)) * 15 + pad`（中文约 2.2 个宽度单位/字，按 `\n` 分段累加）；普通非合并数据行取该行各列估算值的**最大值**。凡是 wrapText 落在合并区，行高必须手写 |

## 五之三、内容完备性核查（覆盖度）

数值一致 + 结构自洽，仍不保证「源文件的内容都被写进了产物」。专做一层**覆盖度核查**，与上述校验并列：

1. **实体清单从源文件派生，不手抄**：把源 docx/xlsx 全量抽成中间文本（段落 / 表格 / sheet 名 / 条目编号），用正则从中间文本派生清单，再逐项到产物里查。手抄清单会漏掉自己没想到的项。
2. **按语义查，不按标号查**：产物若为宣讲/重组版，章节编号与源文件必然不同（源「第二章（一）」→ 产物「2.1」）。查「语义关键词」而非「表号」，否则满屏假阳性。
3. **硬信息必须一字不差**：数字、日期、专有名词、引用的制度名，逐项精确匹配（去标签 + **去全部空白**后再比，消除全角空格/换行差异）；措辞类标题允许等价改写。
4. **重排要留索引**：若产物重排了源文件结构，在产物内附一张**条款索引表**（源条文 ↔ 产物章节），既补全法条骨架的可见性，又让「覆盖完整」可被人工复核。
5. **下行缺失要有去处**：宣讲区不宜出现的敏感数值（如个体金额），不是删掉而是**下沉到受限区**（折叠的内部数据附录），并在原处留一行指引。删掉就等于丢内容。
6. **证伪测试（报「0 缺口」前的必做项）**：注入缺陷，验证检测器真的会报错。**注入时必须删尽该串的全部出现**——只删一处，若该串在文中有 2~3 处冗余（如制度名同时出现在正文与条款索引表、示例值同时出现在正文与附录），检测仍能命中，会得出「校验器失效」的**错误结论**。本轮第一次注入测试即因此误判，删尽后才得到正确结果（4 删 → 4 MISS，一一对应）。
7. **粒度边界要自知**：覆盖度校验测的是「该信息是否存在」，**不测「某处特定位置是否写了」**。信息有冗余时单处遗漏测不出——需要「此处必写」的强约束时，改用**锚定到具体位置**的正则（先框定 `id="sXy"` 区段，再在区段内查找）。


## 五之二、指标型表格（职能表／KPI 表）的额外校验

当单元格是「目标值／及格值」这类**字符串而非数值**时，恒等式检查失效，须改用以下三项：

1. **权重合计恒等式**：`Σ权重 == 100`，且每一维度与其历史出处逐项相等（防止沿用旧权重时改了维度名没改数）。
2. **覆盖性扫描**：遍历「权重映射 → 职能项序号」列，断言表 1-1 的每一项都被至少一处引用，无孤立职能项。
3. **空值 + 结构扫描**：对每张表逐行逐列断言非空，`max_row`/`max_column` 逐一反解。
4. **列角色显式化**（清单型／待填型表格，如整改表、确认表）：把每张表的列分成「应有值列」与「待填白列」两组，断言时分别处理——应有值列逐格非空，待填白列逐格为空。**禁止**用 `range(1, max_column+1)` 统一扫非空。

配套纪律：**指标定义必须与考核权重同源**——同一指标在「定义表」「权重表」「业务落点表」「取数表」四处出现时，描述不得冲突；尤其「分母口径」条款只能有一处定义方，写清谁出数、谁复核。

定义指标时同步写**防操纵条款**（谁有动机做假、对应堵法），比写目标值本身更重要；目标值一律标注「拟订值，报董事长核定」，不得写成既成事实。

## 六、收尾

1. 两个产物都跑完断言，打印「断言全部通过：参数 N 项 + 各表 M 行×K 列 + 锚定档命中」。
2. 对**已部署到交付目录的最终文件**再独立读一次（不要只信生成脚本的输出）。
3. 临时脚本、中间产物用完即删；生成器脚本与 HTML 源留着作溯源。
4. **解释器选择（本机 Windows 实测）**：托管解释器 `<WORKBUDDY_HOME>/binaries/python/versions/3.13.12/python.exe` **不含 `python-docx`**（`ModuleNotFoundError: No module named 'docx'`）。凡脚本要读 `.docx`，一律用 venv：`<WORKBUDDY_HOME>/binaries/python/envs/default/Scripts/python.exe`（含 `docx` + `openpyxl`，Py 3.13.14）。只读 xlsx 的脚本用哪个都行。
5. **门禁顺序**：先跑「生成器 → 断言」，再跑「**独立反解脚本**（不 import 生成器、从落盘文件反解）」，最后才允许交付。反解脚本自身报「不符」时，**先怀疑断言写错，再怀疑产物错**（本轮两次假阳性均属断言错）。
6. **三段式校验，缺一不可**：① 结构自洽（标签配对 / 锚点↔id / 行列数）② 数值一致（落盘反解 + 恒等式）③ **内容完备**（源文件实体 → 产物逐项命中）。只做 ①② 时，「内容漏写」与「排版错位」都能躲过。
7. **每条检查段自证「确实跑了」**：打印抽取条目数，并对条数做非空断言。宁可报「抽取到 0 条」的 FAIL，也不要让空循环输出一个漂亮的「0 项不符」。
